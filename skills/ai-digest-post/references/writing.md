# 書く決まり

## 読者と型

読者は技術者でない、時間が無い人。本文 1,000 字以内（3 分で読める長さ）。4 段で、1 段は 3〜4 文。

| 段 | 書くこと |
|---|---|
| `## 何が起きた` | 出来事を 3〜4 文。固有名詞は初出で一言そえる（「Qwen-Image（アリババの画像生成 AI）」） |
| `## あなたに関係あるか` | 読者を分けて書く。「〜な人: 関係あります」「〜な人: 今は関係ありません」の箇条書きでよい |
| `## やるなら何を` | 具体的な一歩。やらなくてよいなら「今は何もしなくてよい」 |
| `## どのくらい確か` | 出典の種類、誰が測った数字か、分かっていないこと。箇条書きでよい |

## 見出し（title）は最大の要約

読まなくても「何が・どれくらい・どんな条件か、結論」が分かる 1 文にする。本文への誘いにしない。

- 50 字まで。数字は原文の数字だけ
- 使わない: 疑問形、「本当か」「衝撃」などの煽り、「〜した話」「〜してみた」、「〜へ」、「…」
- 英数字の前後に半角空白を入れない
- 例: ×「『AI の覇権が変わる』は本当か。新モデルを公式の数字で確かめた」 ○「DeepSeekの新モデルは安さが本物。公式も『小さな更新』と書き、順位は上位の一角にとどまる」

## 確かさ（confidence）の決め方

記事の芯の主張（何が起きた、見出しの数字）を支える原文で決める。

| 原文 | confidence |
|---|---|
| 作った側の文書・発表に書いてある | 公式の発表 |
| 作った側でない人が動かして測った。論文が支える。自分で試した | 試した結果 |
| 作った本人・投稿した本人の言葉だけ。まとめ記事だけ | 投稿の主張 |
| 原文が無く、推し量った | 推論 |

## 出典（sources）

- 載せるのは、主張を支えた出典だけ。1 本でもよい。本数を増やすための追加の調べはしない（利用者が頼んだ時を除く。このスキルは調べ直さない）
- `kind`: 作った側の文書 `official`、論文 `paper`、GitHub `github`、Reddit `reddit`、X `x`、それ以外（ブログ・ニュース・掲示板）`article`
- `note` は「何が書いてあるか」を一言（リンクの文字になる）
- 転載しない。投稿・掲示板の本文・README・原文の段落を写さない。引用は `note` の中の数語まで

## 裏付けの確かめ方

調べ直しはしない。主張の一覧（記事に書く事実と数字と、その出典の組）を、上から 1 つずつ確かめる。

1. 組にした出典を開く。作った側の発表・文書、論文、リポジトリ、本人の記録なら、そのまま使う。まとめ記事や投稿の言い換えしか無い時は、それが指している一次の出典を開く
2. その主張が書いてあるかを見る。数字・名前・条件（英語だけ、Mac だけ など）が同じかも見る。書いてある所の数語を控える
3. 食い違っていたら、出典に合わせて直す。出典が新しい版になっていたら新しい方に合わせ、4 段目にその旨を書く
4. 確かめられない主張（出典が開けない・書いていない・出典なし）は、その 1 つだけを狭く探す。作った側の発表・文書・リポジトリを検索 1〜2 回で。見つからなければ書かないか、4 段目に「確かめられていない」と書く
5. 作った側でない人の試しや否定の声は、調べ物にすでにあれば使う。無ければ探しに行かず（利用者が頼んだ時を除く）、4 段目に「作った側でない人の確かめは見つけていない」と書く
6. ログインが要る場所（X など）の中身は取りに行かない。URL は出典に残し、それが指す公式やリポジトリで確かめる
7. 有料の壁は回避しない

## 自分で整える時の決まり（yomiyasu が無い時）

意味・数字・言い切りの強さ（断定か推量か）・文の働き（説明・評価・依頼）は変えない。そのうえで次を直す。

- 絵文字、ダッシュ（—）、行の終わりのコロン（：）を使わない
- 英数字の前後に半角空白を入れない（「1 時間」は「1時間」、「Mac で」は「Macで」）
- 比喩の動詞を普通の言葉にする（「倒す」「効く」「溶かす」「爆速」など）。「ようやく」「うっかり」のような含みは残す
- 道具や概念に意志を持たせない（「AI が考えた」は、人か仕組みを主語にする）
- 誰が何をどうしたかが 1 文で分かるようにする。「これ」「それ」の指す物が分かる時は名前に戻す
- 1 文は 30〜45 字を目安に、読点は 1 文に 2 つまで。80 字を超える文は分ける
- 同じ文末（「〜です。」）を 3 回続けない
- 太字と箇条書きを減らす（「あなたに関係あるか」と「どのくらい確か」の箇条書きは型なので残してよい）
- 「重要なのは〜」のような前置きは、評価を述語に移す（「〜が大事です」）

## frontmatter の項目

| 項目 | 書き方 |
|---|---|
| `title` | 上の「最大の要約」 |
| `slug` | 英小文字・数字・ハイフン。URL になる。ファイル名の `<slug>` と同じ |
| `summary` | 1〜2 文、200 字まで。一覧と、LINE などで送った時の説明になる |
| `requested_at` | 調べた日時（JST・秒まで。例 `2026-10-24T09:12:34+09:00`）。一覧の並びの基準で、同じ日の記事も時刻で並ぶ。画面には日付だけ出る。この会話で調べたなら今の時刻（`node -e "console.log(new Date(Date.now()+9*36e5).toISOString().slice(0,19)+'+09:00')"` で取る。推測しない）。履歴や記録から書くなら、その調べた時刻（分までなら秒は `00`）。時刻が分からない時だけ日付だけ（YYYY-MM-DD）。ファイル名の日付は、この日付の部分 |
| `status` | writer は `draft`。publisher・admin は `published` も可（`--publish` でもよい） |
| `tags` | 1〜3 個 |
| `genre` | 1 つ: AIモデル / 画像生成 / 動画生成 / 音声 / 3D・アバター / AIエージェント / 使い方 / 仕事 / ニュースの読み方 / 安全・プライバシー / その他 |
| `related` | 関連する既存の記事の slug（0〜4 本）。分からなければ空のまま |
| `image` | 絵を送る時だけ `/images/YYYY-MM-DD_<slug>.jpg`。無ければ行ごと消す |
| `sources` | 上の「出典」 |
| `confidence` | 上の表 |
| `written_by` | 記事の下に表示される投稿者名。`"投稿者：<登録した名前>"`（`node post.mjs --check` で出る名前）。利用者に頼まれない限り変えない |
| `origin_ref` | 空のまま |

## 書かない物

- 時間の予測（「来週には」）。出典が言っていても「〜と言われているが、書いた時点では未公開」の形にする
- 個人情報、内部の事情、ファイルの場所、鍵
