# ai-digest に記事を書いて投稿する

読者は技術者でない、時間が無い人。3 分で読める 4 段の記事にする。

**このスキルの考え方: 調べ直さない。** 利用者がもう調べた内容（導入を考えて調べた、試してみた、など）を記事にする道具。調べた内容から記事を書き、やり直すのは裏付けの確かめだけ。前に調べた会話は、利用者に選ばせず、自分で探して使う。

**流れ:** 1 話題を決める（曖昧な時だけ確かめる）→ 2 調べた内容を集める（この会話と履歴を自動で）→ 3 裏付けを確かめる → 4〜6 書く・整える・絵 → **7 利用者に見せて OK をもらう（直したら見せ直す）** → 8 送る → 9 報告

このスキルのフォルダ（この SKILL.md がある場所。以下 `$SKILL`）に入っている物:

| 物 | 役目 |
|---|---|
| `scripts/post.mjs` | 鍵を確かめる（`--check`）・記事を送る。要る物は Node.js 22 以上だけ |
| `scripts/check.mjs` | 送る前の確かめ（見出し・4 段・字数・ファイル名・ジャンル・文の癖） |
| `scripts/find-history.mjs` | この PC の Claude Code と Codex の会話の履歴から、話題の言葉で前に調べた会話を探し、関係する問いと答えを抜き出したメモを作る |
| `assets/template.md` | 記事の雛形 |
| `references/setup.md` | 鍵とサイトの URL の登録（初めての時） |
| `references/writing.md` | 書く決まりの全部と、imozuru・yomiyasu が無い時の代わりの手順 |
| `references/images.md` | 絵の決まりと作り方 |

## 0. 始める前に（毎回）

### 鍵を確かめる

```bash
node "$SKILL/scripts/post.mjs" --check
```

- 「鍵は有効です」なら、名前と役を覚えておく。writer は下書きまで、publisher は自分の記事を公開できる、admin は誰の記事でも公開できる
- 「見つからない」「鍵が違う」なら、`references/setup.md` を読み、利用者に登録の手順を案内する。登録は利用者が自分のターミナルで行う。**鍵を AI との会話に貼ってもらわない**。貼られてしまったら、その鍵は使い続けず、運営に作り直しを頼むよう伝える
- 記事を書くのは鍵が無くても進めてよい。送るのは登録が済んでから
- Codex で「サイトにつながらない」と出たら、サンドボックスがネットを止めていることが多い。利用者の承認を得て、サンドボックスの外で実行する

### 使える道具を確かめる

あれば使い、無ければ代わりの手順で進める。どちらにしたかは最後の報告に書く（黙って飛ばさない）。

| 道具 | 有無の見方 | ある時 | 無い時 |
|---|---|---|---|
| imozuru（原文を落とす道具がある） | 自分のスキルの一覧にあるか。一覧が見えなければ `~/.claude/skills/imozuru/`・`~/.codex/skills/imozuru/`・`~/.agents/skills/imozuru/` のどれかに SKILL.md があるか | 3 で出典を落として確かめる（何周もの調べ直しには使わない） | 3 で出典を自分で開いて確かめる |
| yomiyasu（日本語を読みやすく整える） | 同じ見方で yomiyasu | 5 で本文を整える | 5 の「自分で整える」 |
| 絵を作る道具 | Codex は内蔵の画像生成（`$imagegen`）。Claude Code には無い | 6 で絵を作る | 絵なしで送るか、利用者が権利を持つ写真を使う |

呼び方: Claude Code は Skill ツールで呼ぶ。Codex はそのスキルの SKILL.md を開き、書いてある手順で進める。

## 1. 話題を決める

| 頼まれ方 | すること |
|---|---|
| **はっきりしている**（「〇〇を記事にして」のように、記事にする物・出来事の名前がある） | 確かめずに 2 へ進む。7 で記事を見せるまで、利用者に何も聞かずに進める |
| **曖昧**（「今の会話を記事にして」「これを記事にして」「さっきのを記事に」「記事にして」だけ。会話に話題がいくつもあって、どれか決まらない時も） | 会話から話題を 1 つに絞り、「『〇〇』の記事化で間違いないですか？」と聞いて返事を待つ。直されたら、直された話題で進む。返事が来るまで先へ進まない |

- 決めた話題から、履歴を探す言葉を 3〜8 個作る。物の名前・英語の名前・カタカナ・略称・別名・型番。「AI」「使い方」「記事」のように、どの会話にも出る言葉は入れない

## 2. 調べた内容を集める（調べ直さない・利用者に選ばせない）

元にする物は 3 つ。全部、自分で集める。

| 元 | 使い方 |
|---|---|
| この会話 | 利用者と読んだページ、試した結果、分かったこと。前半が要約されていても、要約にある事実と出典の組を拾う |
| この PC の会話の履歴 | 下の `find-history.mjs` で、Claude Code と Codex の会話の記録を話題の言葉で探す。**毎回探す** |
| 利用者が渡した記録 | メモ・報告のファイル、imozuru の調べ物のフォルダ（`~/research/<話題>/` の `map.md`・`sources/`・`report.html`）。渡された時は全部読む |

### 履歴を探す

```bash
node "$SKILL/scripts/find-history.mjs" --query "言葉1 言葉2 言葉3"
```

- 当たった会話を関係の強い順に 5 つまで出し、会話ごとにメモ（関係する問いと答え・開いた URL・検索した言葉の抜き出し）を書く。メモは上から読み、話題の違う会話は使わない。足りたら途中でやめてよい
- どの会話を使うかは自分で決める。利用者に聞かない
- いま話している会話は探す先から外れる。「この会話（…）: 要約されているので…」と出たら、そのメモも読む（要約で消えた細部と出典が入っている）
- 当たりが無い・外れている時は、言葉を変えて 1〜2 回探し直す（別名・英語の名前・略称）。探し直すのは手元の履歴だけで、Web を調べ直さない
- 終わりの番号が 3 なら、読めなかった会話がある（記録の形が変わったか、壊れている）。結果は使い、報告に書く。4 なら、探さない場所の設定（`~/.config/ai-digest/history-ignore`）があるのに読めないので、履歴を探していない。この会話と渡された記録だけで進め、設定を直すよう利用者に伝える。2 は使い方の誤り
- メモには、利用者の個人的な話・人の名前・ファイルの場所・内部の事情も入っている。記事に使うのは、調べた事実と出典だけ
- 「探さない設定」と出たら、利用者が履歴を探さないと決めている（`~/.config/ai-digest/history-ignore` に `*` の行）。この会話と渡された記録だけで進める

### 集めた後

- **主張の一覧** を作る。記事に書く事実と数字を 1 行ずつ、それを支えた出典（URL かファイル）と組にする。出典の分からない主張には「出典なし」と印を付ける
- 記事の芯を 1 行にする（何が、どれくらい、どんな条件で）。調べた内容から外れた芯にしない
- **どこにも調べた内容が無い時**（この会話にも、履歴にも、渡された記録にも無い）は、調べ始めない。「前に調べた記録が見つかりませんでした。このスキルは調べた内容を記事にする道具です。先に調べるか、調べた記録を渡してください」と伝えて止まる。利用者が「ここで調べて」と言った時だけ調べる（imozuru があれば使う）

## 3. 裏付けを確かめる（やり直すのはここだけ）

- 主張ごとに、組にした出典を開き直し、その主張が書いてあるかを確かめる。書いてある所を短く控える（数語の引用と場所）。履歴のメモにある数字も、メモを信じずに出典で確かめる
- 結果は 3 つに分ける。確かめられた／出典と食い違う（数字や名前が違う・版が新しくなって変わった）／確かめられない（出典が開けない・書いていない・出典なし）
- 食い違った主張は、出典に合わせて直す
- 確かめられない主張は、**その 1 つだけを狭く探す**（作った側の発表・文書・リポジトリを、検索 1〜2 回で）。それでも無ければ、本文に書かないか、4 段目に「確かめられていない」と書く
- **imozuru がある時**は、出典を imozuru の `scripts/fetch.py` で落としてから確かめる（PDF の文字や YouTube の字幕も読める）。落とす先は `~/research/ai-digest-<slug>/sources/`。imozuru の調べ物（何周もの検索）はしない。`fetch.py` が動かない時（Python 3.10 未満など）は、自分で開いて確かめる
- **無い時**は、出典を自分で開いて確かめる。手順は `references/writing.md` の「裏付けの確かめ方」
- 確かさ（`confidence`）は、確かめられた出典の種類で決める（writing.md の表）
- 検索語に、人の名前や内部の事情を入れない（検索語は外に出る）

## 4. 書く（決まりの全部は `references/writing.md`）

- `assets/template.md` を写して、ファイル名を `YYYY-MM-DD_<slug>.md` にする（日付は調べた日）
- 本文は 4 段: `## 何が起きた` → `## あなたに関係あるか` → `## やるなら何を` → `## どのくらい確か`。1,000 字以内
- 見出しは「最大の要約」。読まなくても何がどれくらいか分かる 1 文で、50 字まで。疑問形・煽り・「〜した話」「〜へ」・「…」は使わない
- 転載しない。投稿・掲示板・README・原文・会話の言葉を写さず、出典は要約とリンクにする
- `genre` は 1 つ。`written_by` は `"投稿者：いんきょ"` のまま

## 5. 文を整える

- **yomiyasu がある時**: 本文（frontmatter を除く）を `--domain business` で渡す。渡す前に写しを取り、戻ったら 4 つの見出し・数字・URL・否定（〜ない）が写しと同じかを比べる。yomiyasu の「書き手に確かめたい点」は本文に足さず、7 で記事を見せる時に利用者に聞く
- **無い時**: `references/writing.md` の「自分で整える時の決まり」
- 最後に必ず `node "$SKILL/scripts/check.mjs" <記事.md>`。「直す」が出たら直す。「見る」は読んで判断する

## 6. 絵（任意。決まりと作り方は `references/images.md`）

- Codex: 内蔵の画像生成で、記事の中身を 1 場面の「物」の絵にする。出来た絵を `$CODEX_HOME/generated_images/`（既定は `~/.codex/generated_images/`）から記事の横へ写し、決まりの名前にする
- Claude Code: 絵を作る道具は無い。利用者が権利を持つ写真を使うか、絵なしで送る（サイトはジャンルの色の板を出す）
- 絵は自分の目で確かめる。文字・ロゴ・実在の製品・人の顔が入っていたら作り直す

## 7. 利用者に見せて OK をもらう（送る前に毎回）

check.mjs を通った記事を、次の順で見せる。

1. 見出し・要約・ジャンル・タグ・確かさ
2. 本文の全部（4 段そのまま。縮めない）
3. 出典の一覧
4. 絵（ファイルの場所。無ければ「絵なし」）
5. 元にした調べ物（この会話・使った履歴の会話の日付と道具と依頼・渡された記録）と、裏付けの結果（確かめられた・直した・書かなかった主張）
6. 送り方（「下書きで送る」か「公開まで行う」。公開まで行うのは、利用者が公開を頼んだ時だけ。writer の鍵は下書きだけ）

そのうえで「この内容で投稿してよいですか？ 直したい所があれば教えてください」と聞き、返事を待つ。

- 直しを頼まれたら、直して check.mjs を通し直し、**直した後の全部をもう一度見せて**聞く。直しの頼みに「それで投稿して」と添えてあっても、直した物を見せて確かめ直す
- これを OK が出るまで繰り返す。OK は「OK」「いいよ」「投稿して」など、送ってよいとはっきり分かる返事。曖昧なら聞き直す
- OK が出るまで送らない（下書きも送らない）

## 8. 送る（7 で OK が出てから）

```bash
node "$SKILL/scripts/post.mjs" <記事.md> [--image <絵>]...   # 下書き
node "$SKILL/scripts/post.mjs" <記事.md> --publish            # 送ってすぐ公開（publisher・admin だけ）
```

- 返事の `ok` と `status` を見る。`errors` があれば直して、同じ slug で送り直す（書き換えになる）。中身を変えたなら、7 で見せ直してから送る
- writer の鍵なら下書きまで。公開は運営が確かめてから行う

## 9. 利用者への報告

1. 送った結果（下書きか公開か・slug）。下書きなら「運営の確かめを待つ」
2. 元にした調べ物: この会話・履歴から使った会話（日付・道具・場所・依頼の頭）・渡された記録。履歴を探した言葉と、当たった会話の数・読めなかった会話の数
3. 裏付けの結果（主張の数・確かめられた数・直した数・書かなかった数）
4. 使った道具: imozuru・yomiyasu・絵の道具を使ったか。無くて代わりの手順にした時は、そう書く

## 10. やらない

- 鍵を会話・記事・コマンド行に書かない。利用者に鍵を貼ってもらわない
- 利用者の OK の前に送らない。曖昧な頼みの時に、話題を確かめずに書き始めない
- 他人の記事や絵を書き換えない。確かでない数字を書かない
- テーマだけで Web を調べ直さない（利用者が頼んだ時を除く）
- 履歴のメモにある個人的な話・人の名前・ファイルの場所・内部の事情・会話の言葉そのものを記事に書かない
- 「来週には」などの時間の予測を書かない
